# Reversal, home amount popup, and fallback — v2.0.4

## Findings and changes

### Reversal

The production code persists the recovery record before sending, sends 0400 after an uncertain exchange, validates response MTI/STAN/response code (and MAC when enabled), and clears recovery after a valid 0410/00. Exhausting automatic retries retains the record and blocks new financial transactions and settlement. Contact-chip approval stays pending until chip completion; failed completion reverses the authorization.

Fixed a packet consistency issue: preauthorization reversals now preserve DE14 expiry for all brands when the original preauthorization included it. Previously the reversal expiry condition omitted the PREAUTH path.

Added loopback-host integration tests using the actual OnlineHost builders, HostComm TCP framing, ISO packing/parsing, and explicit in-memory preferences. They exercise approval, decline, lost replies, mismatched original responses, invalid reversal MTI/STAN, unacknowledged recovery blocking a new sale, chip completion/decline, restart recovery, connection refusal, preauthorization expiry, and the actual delayed retry worker. These do not contact a bank host or validate real PIN-pad MACs. Storage tests simulate reopening saved preferences; they do not simulate a physical power failure.

### Home-screen amount popup

v2.0.3 removed the popup's card watcher at the vendor's request. This update restores card-triggered amount entry through passive `isCardInserted()` observation. PayActivity makes no openFindCardForEMV/closeFindCardForEMV calls. A shared lock keeps home sensor reads out of active transaction reader work. Debounced insertion opens the SALE keypad once; removal dismisses only a sensor-opened keypad. Explicit transaction selection and menu permissions take precedence. Lifecycle tokens discard stale callbacks.

The installed SDK exposes no insertion event in ICardBinderService; the slot sensor is sampled on a background thread. Correct idle sensor reporting still needs physical-device confirmation. Diagnostic logs use `HOME_SLOT present=...` and `HOME_SLOT amount keypad opened`.

### Fallback

The existing classifier accepted only IC_CARD and -2011. SDK v356 also defines -2005 (chip detection), -2006 (chip power-on), and -2007 (chip reset), which were being ignored. These completed failures now count. Timeout (-2003) and generic find failure (-2009) count only with observed chip insertion; empty timeouts, cancellation, busy, RF, and stripe failures do not.

The counter waits for the SDK result. An unreadable chip may therefore take the full 30-second search window. The existing three-failure confirmation, card-removal check, stripe-only fallback search, and fallback entry mode remain in use. Successful chip data clears the counter after a valid PAN is available.
